# Puzzle Harbour — Technical SEO / Indexability Audit

**Date:** 19 September 2026  
**Scope:** Vite + React SPA on Cloudflare Workers (`puzzleharbour.com`)  
**Constraint:** Inspection only. No code changes and no deploy were made for this audit.

Google Search Console at the time of the audit:

- ~49 URLs discovered
- 3 indexed
- 46 listed as **Discovered – currently not indexed**
- Affected URLs include category pages, puzzle pages, and `/play`

**Headline:** This is a production HTML problem, not a sitemap or robots problem. Google has 49 URLs because the sitemap is complete. Almost none are indexed because **every public URL currently returns the same empty SPA shell**.

The following URLs were fetched as Googlebot, with no JavaScript:

- `/`
- `/category/animals`
- `/puzzle/autumn-forest`
- `/spot-it/night-carnival`
- `/play`

All five returned **HTTP 200**, **0 redirects**, **1621 bytes**, the **same homepage `<title>`**, **no canonical**, **no H1**, **0 `<a href>` links**, and `<div id="root"></div>`.

That matches Search Console: 49 discovered, 3 indexed, 46 “Discovered – currently not indexed.”

## 4. Raw HTML / prerendering

### What Google gets before JS

Every representative URL is the Vite shell from `index.html`:

- **Title:** `Story Puzzles & Spot it — Free Jigsaw Puzzles | Puzzle Harbour`
- **Description:** homepage copy only
- **Canonical:** missing
- **H1:** missing
- **Body:** empty `#root`
- **Internal links:** none

`/category/animals` and `/puzzle/autumn-forest` are **not** page-specific. They are the same generic app shell.

### How prerendering is supposed to work

1. `npm run build` → Vite writes the SPA shell.
2. `postbuild` runs `scripts/prerender.mjs`.
3. Playwright opens each of the 49 routes against that shell.
4. It waits for `useSeo` (`data-seo-path` / `og:url`).
5. It writes `dist/{path}/index.html`.
6. The worker serves those snapshots first.

`useSeo` writes title, description, canonical, OG, and robots **only in a `useEffect`**. Without a successful Chromium snapshot, none of that exists in the first HTML byte.

On the last production deploy, prerender **failed** and the build **continued with sitemap only**. Production now has a sitemap of 49 unique URLs pointing at 49 copies of one empty page.

## 5. Canonical tags

**Intended (after JS):** self-referencing, via `useSeo` + `SITE_URL`.

Examples that *should* exist:

- `/` → `https://puzzleharbour.com/`
- `/category/animals` → `https://puzzleharbour.com/category/animals`
- `/puzzle/autumn-forest` → `https://puzzleharbour.com/puzzle/autumn-forest`

**In the HTML Google actually receives:** no canonical on any of those URLs.

So Google cannot tell `/category/animals` from `/`. That is a strong duplicate / soft-404 signal.

Canonicals are omitted for `noindex` routes (`/my-puzzles`, `/play/:code`, custom puzzles, unknown slugs). That part of the code is fine.

## 6. noindex / headers

No `X-Robots-Tag` on the live responses.

`noindex` is only set in JS, after hydration:

| Route | noindex? |
|---|---|
| Public category / puzzle / stories / spot-it / `/play` | `index, follow` |
| `/my-puzzles` | `noindex, nofollow` |
| `/play/:code` | `noindex` |
| `/puzzle/custom/:id` | `noindex` |
| Unknown category/story/spot slug | `noindex` |

No public page is *intended* to be noindex. But the live HTML has **no robots meta at all**, so this is not what is blocking indexing. Duplicate empty HTML is.

## 7. Internal linking

**In the React source, linking is mostly real `<Link>` / `<a href>`:**

- Home browse cards → `/category/{slug}`
- Category cards → `/puzzle/{id}`
- Footer → all categories, stories, Spot it, `/play`
- Header → `/play`, `/stories`, `/spot-it`

**That does not help Google right now**, because none of those links exist in the raw HTML.

**Weak / broken for crawlers even after JS:**

- Home sample puzzles and the daily card are `<Link>`s with `preventDefault()`. The `href` is in the DOM, but click navigation is JS-only. Fine if prerendered; useless in the current empty shell.
- Home samples use `?pieces=` / `?rotate=` while sitemap/canonicals are clean `/puzzle/{id}`. Minor.

If prerender is restored, the graph is: home → 5 categories → all 34 puzzles (2 clicks). Stories and Spot it are 1–2 clicks via header/footer.

## 11. `/play`

Treat it as a **functional route**, not a search landing page.

- It creates/joins a room. Almost no unique text.
- It is in the sitemap and is meant to be indexable.
- It will compete with real puzzle/category pages once HTML is unique again.

**Recommendation:** `noindex` `/play` and `/play/:code`, and drop `/play` from the sitemap. Keep it in the header for users.

## A. Most likely causes (ranked)

1. **Very high — Production is serving the same empty SPA shell for all 49 URLs.** Last deploy’s prerender failed; snapshots are missing; Cloudflare SPA fallback returns `index.html` everywhere. Google sees 49 duplicate empty pages.
2. **Very high — Title, description, canonical, H1, and links are JS-only** (`useSeo` in `useEffect`). Google’s first response has none of them.
3. **High — Soft-404 / duplicate-content behavior.** “Discovered – currently not indexed” is what Google does when the sitemap lists URLs that all look like the homepage.
4. **Medium — Puzzle pages are thin even when prerendered** (title + one sentence + canvas). They need unique first-byte HTML to have a chance.
5. **Low — `/play` in the sitemap** and sample/daily `preventDefault()` links. Secondary. Not why 46 URLs are stuck.

| File | Role |
|---|---|
| `scripts/prerender.mjs` | Builds sitemap; prerender can fail and still “succeed” |
| `wrangler.toml` | SPA fallback when snapshots are missing |
| `worker/index.js` | Serves snapshot if present, otherwise the shell |
| `src/hooks/useSeo.ts` | All SEO tags only after React runs |
| `index.html` | The generic shell now served on every URL |
| `src/pages/Home.tsx` | Sample/daily `preventDefault()` |
| `src/pages/PlayTogether.tsx` | `/play` is indexable despite being a tool |

---

## C. Recommended fixes (by impact)

1. **Restore prerender on deploy.** Install Playwright Chromium, **fail the build** if prerender fails, confirm `dist/category/`, `dist/puzzle/`, etc. exist, then redeploy.
2. **Verify first-byte HTML** for `/category/animals` and `/puzzle/autumn-forest`: unique title, canonical, H1, links, no empty `#root`.
3. Optionally put a static `<link rel="canonical">` / unique title in each snapshot (prerender already does this when it works).
4. `noindex` `/play` and remove it from the sitemap.
5. Remove `preventDefault()` on home sample/daily cards so `href` is a real navigation.
6. Align title suffix to `Puzzle Harbour` (cosmetic).

---

## D. Safe to do immediately

- Re-run a **successful** prerender + deploy (highest impact, no content rewrite).
- Make prerender failure fail the build (prevents this from happening again).
- `noindex` `/play` + drop it from the sitemap.
- Stop `preventDefault()` on crawlable home links.

Do **not** add SEO filler copy yet. It will not help while every URL returns the same 1621-byte shell.

---

## E. Bots vs browsers

**Yes — they see different pages.**

- **Googlebot / curl (no JS):** identical homepage shell, empty `#root`, no links, no canonical.
- **A normal browser:** React runs, `useSeo` writes unique tags, and the real page appears.

That is exactly the SPA gap the prerender pipeline was built to close. It is currently broken in production.
